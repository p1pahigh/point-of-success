# Подключение к проекту The Point of Success

Сайт онлайн-школы делают двое, каждый со своего компьютера и своего аккаунта Claude. Общая копия лежит в закрытом хранилище на GitHub: https://github.com/p1pahigh/point-of-success

## Часть 1. Для человека (10 минут)

1. Зарегистрируйтесь на GitHub: https://github.com/signup
2. Пришлите свой логин на GitHub владельцу проекта. Он пригласит вас в хранилище.
3. Примите приглашение. Оно придёт на почту или появится здесь: https://github.com/notifications
4. Установите Claude Code: https://claude.com/claude-code
5. Откройте Claude Code, приложите к сообщению этот файл и напишите:
   > Сделай всё по этой инструкции

Дальше Claude всё сделает сам. Один раз он попросит вас ввести команду в терминал и подтвердить вход в GitHub в браузере.

## Часть 2. Для Claude

Ты помогаешь другу владельца проекта подключиться к общему репозиторию. Общайся с ним по-русски, простым языком, без терминов, коротко. Он может не знать, что такое Git и терминал. Каждый шаг, который он делает сам, объясняй отдельно и жди ответа.

### Шаг 1. Проверить систему и Git

- Определи систему (macOS, Windows, Linux) и процессор (`uname -m` на Mac: `arm64` — Apple, `x86_64` — Intel).
- Проверь `git --version`. Если Git нет:
  - macOS: `xcode-select --install`. Человек сам нажимает «Установить» в появившемся окне.
  - Windows: `winget install --id Git.Git -e` или установщик с https://git-scm.com/downloads

### Шаг 2. Установить GitHub CLI (`gh`)

Проверь `gh --version`. Если `gh` нет:

- **macOS.** Homebrew может не быть. Установщик `.pkg` macOS не открывает (окно «Apple не удалось подтвердить…»), поэтому бери архив с бинарником под нужный процессор:
  - Apple: https://github.com/cli/cli/releases/download/v2.104.0/gh_2.104.0_macOS_arm64.zip
  - Intel: https://github.com/cli/cli/releases/download/v2.104.0/gh_2.104.0_macOS_amd64.zip

  Скачай его через `curl` во временную папку и распакуй. Файл, скачанный через `curl`, macOS не блокирует. Затем нужно положить `bin/gh` в `~/.local/bin/` и проверить, что эта папка есть в `PATH`. У владельца проекта Claude Code не дал Claude поставить программу самому. Если и тебе откажут, дай человеку готовую команду одной строкой, например `mkdir -p ~/.local/bin && cp <путь>/bin/gh ~/.local/bin/ && gh --version`, и попроси вставить её в терминал.
- **Windows:** `winget install --id GitHub.cli -e` или MSI-установщик со страницы https://github.com/cli/cli/releases/latest
- **Linux:** инструкция на https://github.com/cli/cli#installation

### Шаг 3. Войти в GitHub

Вход интерактивный, поэтому его делает человек в своём терминале. Попроси его вставить:

```
gh auth login --web --git-protocol https
```

Объясни ему:
- на вопрос «Authenticate Git with your GitHub credentials?» ответить **Y**;
- терминал покажет код из 8 символов. Код нужно вставить **в браузере** на https://github.com/login/device, а не присылать тебе;
- нажать **Enter** в терминале, затем **Authorize** в браузере;
- готово, когда терминал напишет «Logged in as <логин>».

Потом проверь сам: `gh auth status`, затем `gh auth setup-git`.

### Шаг 4. Скачать проект

1. Проверь доступ: `gh repo view p1pahigh/point-of-success`. Если ответ «not found», приглашение ещё не принято (см. часть 1, пункты 2–3).
2. Скачай проект в папку «Загрузки»: `git clone https://github.com/p1pahigh/point-of-success.git ~/Downloads/point-of-success`. На Windows — в `%USERPROFILE%\Downloads\point-of-success`.
3. Настрой автора коммитов только для этого репозитория, без личной почты:
   - `git config user.name "<логин>"`
   - `git config user.email "<id>+<логин>@users.noreply.github.com"`

   `id` и логин возьми из `gh api user --jq '.id,.login'`.

### Шаг 5. Прочитать CLAUDE.md и начать работу

Прочитай `CLAUDE.md` в папке проекта **целиком**: там правила, договорённости и история работы. Учти три вещи.

- **CLAUDE.md написан для владельца проекта**, «заказчик» там — это он. Человек, с которым ты сейчас говоришь, его друг и соавтор. Правила о стиле, текстах и согласовании действуют и для него. Открытые вопросы из CLAUDE.md адресованы владельцу: не задавай их другу, а спроси, знает ли он ответы.
- **Раздел «Совместная работа» обязателен.** В начале работы — `git pull`. После каждой законченной правки сразу, без напоминаний: `git pull`, совместить правки, прогнать проверки, коммит с понятной русской подписью, `git push`. Принудительную отправку (`push --force`) не делать никогда. Если одну строку поменяли оба, покажи человеку обе версии и спроси, какую оставить.
- **Инструменты проверки сделаны под Mac владельца.** `tools/tests/run.sh` и `tools/snap.swift` работают только на macOS. Подсказки про Safari касаются компьютера владельца. На Windows и Linux открывай сайт в любом браузере и честно говори, что автоматические проверки не запускались.

В конце коротко расскажи человеку, что за проект, как устроена совместная работа (одна-две фразы), и спроси, что он хочет сделать. Предложи договориться с владельцем, кто какую часть сайта правит.
